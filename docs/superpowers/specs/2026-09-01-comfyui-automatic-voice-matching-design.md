# ComfyUI 自动声音资产匹配设计

- 日期：2026-09-01
- 状态：已确认，待实施
- 范围：TTS More 剧本语义分析后的声音资产推荐与 ComfyUI 生成衔接
- 参考资产目录：`E:\训练\GPT-SoVITS-v2ProPlus-Portable-20260611`

## 1. 背景

TTS More 已能从混乱剧本中提取角色、情绪和台词，并允许部分成功和人工确认。当前后续配音仍主要依赖用户手动选择角色绑定、GPT/SoVITS 权重、参考音频和推理参数。

本功能在语义分析和生成队列之间增加一个可解释的声音资产匹配层。它根据已经确认的角色、情绪、台词语言和目标时长，从 ComfyUI 已注册且可执行的资源中选择最合适的模型权重和参考音频。高置信度结果只自动填入，不自动发起生成；用户始终可以查看候选、试听并覆盖。

生成链路只经过 ComfyUI，不直接调用 GPT-SoVITS Portable API。

## 2. 第一性原则

系统必须先保证“声音身份正确”，再优化“情绪和时长相似”。错误地给命名角色换成另一个角色的声音，比没有自动推荐更糟。因此：

1. **身份是硬约束**：命名角色没有合法同角色资源时保持未匹配。
2. **可执行性是硬约束**：发现到的权重不等于可生成资源，只有 ComfyUI 返回为 `ready` 且完成映射的 `resource_id` 才能参选。
3. **排序必须可解释和可复现**：同一语义输入与目录版本必须得到相同结果，不由大模型直接决定最终选择。
4. **人工选择优先**：人工确认和锁定结果不能被重新扫描或重新排序静默覆盖。
5. **失败局部化**：一条台词无法匹配不能阻塞其他台词。
6. **核心逻辑轻量**：首版采用字段硬筛选和确定性加权排序，不引入声纹向量库、训练流水线或新的数据库。

## 3. 目标

- 扫描可配置 Portable 资产目录，索引 GPT/SoVITS 权重与参考音频。
- 从 ComfyUI 查询资源、节点类型、引擎能力和就绪状态。
- 维护 Portable 资产与 ComfyUI `resource_id` 的明确映射。
- 对已确认台词返回前三名候选、分项得分、理由和置信度。
- 高置信度候选自动填入模型、参考音频、情绪、目标时长和安全语速。
- 支持试听、手动替换、锁定以及角色级复用。
- 提交生成时保存不可变选择快照，并由现有 ComfyUI 队列执行。
- 提供资产同步和诊断页面，显示未注册权重、缺失元数据和插件能力。

## 4. 非目标

- 不直接调用 Portable 的 `/tts`、`/set_gpt_weights` 或 `/set_sovits_weights`。
- 不向 ComfyUI 工作流传入任意本地权重路径。
- 不允许命名角色自动跨角色选择声音。
- 不自动提交生成任务。
- 不实现声纹、音色或文本向量检索。
- 不训练黑盒排序模型。
- 不在产品运行时静默下载或升级 ComfyUI 插件。
- 不要求本轮为所有 IndexTTS、CosyVoice 资源补齐自动匹配元数据。

## 5. 已确认决策

### 5.1 跨角色策略

- 命名或具体角色只能使用以下关系之一：人工确认绑定、规范名一致、受控别名一致。
- 仅路人、旁白、士兵等明确标记为通用角色的台词可以进入通用声音池。
- 角色名称相似、人物设定相似或大模型推测相似都不能绕过该规则。

### 5.2 缺失元数据

- 音频时长、文件指纹等客观字段自动测量。
- 语言优先根据已声明文本确定，缺失时使用确定性语言检测。
- AI 可以从文件名、已有提示文本和声明元数据推断缺失的角色或情绪标签。
- AI 推断不得覆盖人工确认或配置声明。
- 低置信度角色标签不能驱动命名角色的自动填入。
- 首版信任下限为：角色推断 `>= 0.90`、情绪推断 `>= 0.75`；低于下限必须人工确认。资源与权重组的兼容关系不能由 AI 推断，必须来自插件声明或人工确认。

### 5.3 自动化程度

- 高置信度结果自动填入，但不提交生成。
- 页面始终显示前三名候选、分项得分和命中理由。
- 中低置信度结果只展示推荐或保持未匹配。
- 人工选择可以保存为角色级绑定并优先用于后续台词。

### 5.4 执行方式

- TTS More 负责目录、约束、排序、人工确认和选择快照。
- ComfyUI 负责模型加载、推理、排队和音频输出。
- 每组可执行模型权重由一个稳定的 ComfyUI `resource_id` 表示。

## 6. 总体架构

### 6.1 剧本语义层

沿用现有语义分析和人工确认流程，输出：

- 角色规范名、受控别名和角色类型；
- 台词原文及源文本区间；
- 规范化情绪与证据；
- 台词语言与分析置信度。

该层不接触权重文件，也不决定声音。

### 6.2 声音资产目录层

新增轻量、文件存储的目录服务，负责：

- 扫描一个或多个配置允许的资产根目录；
- 读取 Portable 的 `character_map.json`、`参考音频/audio_metadata.json` 和权重目录；
- 测量参考音频时长、计算文件指纹、规范化语言和情绪；
- 查询 ComfyUI `/capabilities`、`/object_info` 或插件提供的等价能力接口；
- 构建不可变 `CatalogSnapshot`，验证成功后原子替换当前快照；
- 保留上一份有效快照，以便扫描失败时继续展示和诊断。

Portable 扫描器只负责“发现资产”。GPT 与 SoVITS 权重的权威配对来自 ComfyUI 资源配置或人工确认映射。系统不得仅因文件名、角色名或当前 `weight.json` 同时出现两个路径就假定它们构成可执行权重组。

### 6.3 自动匹配层

匹配器接收一条已确认语义台词和一个目录快照，先执行硬校验，再对合法候选进行确定性排序。它不调用大模型，不访问文件系统，不提交生成任务，因此可以纯函数方式测试。

输出包含：

- 前三名 `VoiceCandidate`；
- 每项分数、总分和稳定的排序理由；
- 自动填入资格与阻断原因；
- 目标时长和建议语速；
- 使用的目录版本。

### 6.4 选择与复核层

页面允许用户试听候选参考音频、切换候选、编辑参数、保存角色绑定和锁定选择。人工选择来源记录为 `manual`，自动填入记录为 `automatic`。人工来源永远优先。

自动匹配不得为命名角色跨角色选声。专家手动选择器可以在明确显示身份不一致并要求二次确认后覆盖该限制；这种选择记录为 `manual_identity_override`，不能自动升级为全局角色别名，也不能让后续台词自动跨角色。人工覆盖仍必须满足资源可执行、路径安全和资产完整性要求。

### 6.5 ComfyUI 执行层

生成仍使用现有服务路由、任务队列、负载签名和 ComfyUI 工作流构建器。匹配功能只向生成任务提供已经验证的 `resource_id`、参考音频资产、文本语言、参考语言、提示文本、语速和现有采样参数。

## 7. 数据契约

### 7.1 元数据值

每个可推断字段使用统一包装：

```text
MetadataValue<T> = {
  value: T | null,
  origin: measured | declared | inferred | confirmed,
  confidence: 0..1,
  evidence_kind: filename | sidecar | transcript | audio_probe | user | null
}
```

来源优先级按字段类别确定，不能使用一个全局顺序：

- 角色、别名、情绪等语义字段：`confirmed > declared > inferred`。
- 时长、采样率、声道等客观字段：`measured > confirmed > declared > inferred`。
- 语言：人工确认或明确声明优先；否则使用文本语言检测，AI 推断只作为最后回退。

AI 补全只在资产首次出现或内容指纹变化且字段仍缺失时执行，结果随目录快照缓存。目录版本包含推断值、推断规则版本和提供者标识，推荐阶段不会再次调用大模型。

### 7.2 ComfyUI 声音资源

```text
VoiceResourceRecord = {
  resource_id,
  engine_type,
  state: ready | unavailable | incompatible,
  character,
  aliases,
  is_generic,
  weight_artifact_ids,
  capability_contract_version,
  mapping_origin,
  fingerprint
}
```

`weight_artifact_ids` 是目录内稳定标识，不向前端或日志返回完整绝对路径。

### 7.3 参考音频

```text
ReferenceAssetRecord = {
  asset_id,
  root_id,
  relative_path,
  character,
  emotion,
  language,
  prompt_text,
  duration_ms,
  compatible_resource_ids,
  fingerprint,
  metadata_quality
}
```

持久化使用 `root_id + relative_path`。每次读取都重新解析并检查最终路径仍位于允许根目录内。

### 7.4 候选

```text
VoiceCandidate = {
  candidate_id,
  resource_id,
  reference_asset_id,
  engine_type,
  score,
  score_breakdown,
  reasons,
  target_duration_ms,
  suggested_speed,
  auto_fill_eligible,
  blockers,
  catalog_version
}
```

### 7.5 选择快照

```text
VoiceSelectionSnapshot = {
  line_id,
  source: automatic | manual | role_binding,
  resource_id,
  resource_fingerprint,
  reference_asset_id,
  reference_fingerprint,
  catalog_version,
  emotion,
  target_duration_ms,
  speed,
  inference_parameters,
  selected_at
}
```

提交任务后该快照不可变。后续目录变化不能修改已经入队的任务。

## 8. 目录同步与映射

同步按以下顺序执行：

1. 解析并验证所有允许根目录。
2. 发现权重和参考音频，读取旁路元数据。
3. 测量客观字段并生成内容指纹。
4. 按字段类别合并元数据，遵守对应来源优先级。
5. 查询 ComfyUI 资源和节点能力。
6. 使用插件明确返回的资源信息或人工映射连接 `resource_id` 与权重组。
7. 校验受控别名不存在歧义，并校验参考音频和资源的角色兼容关系。
8. 构建新快照并执行完整校验。
9. 校验成功后原子发布新版本；失败时保留上一有效版本。

资产根目录只来自操作员控制的 ComfyUI 服务配置 `default_params.voice_asset_root`，或环境变量 `TTS_MORE_GPT_SOVITS_PORTABLE_ROOT`。测试可以直接注入临时根目录；浏览器 API 不接受或修改资产根路径。

发现但未映射的权重显示为“待注册”，不能参加排序。ComfyUI 已有资源但不能提供完整匹配契约时显示为“仅手动选择”。

资源生命周期固定为：`discovered -> mapped -> registered -> reload_required -> ready`。TTS More 内的映射不能替代 ComfyUI 插件注册；新增或修改 ComfyUI 资源配置后必须重载或重启 ComfyUI，并以新的能力响应确认 `ready`。首版不在扫描过程中自动写入插件配置，以避免目录扫描意外改变执行环境。

目录版本由规范化记录、资源状态和内容指纹共同计算；文件修改、映射修改或资源就绪状态变化都会产生新版本。参考音频使用内容哈希；大型权重使用规范化相对路径、文件大小、修改时间和 ComfyUI 资源配置指纹，避免每次扫描完整读取大模型文件。同步由单写者锁保护，相同请求合并执行，读取方始终读取完整不可变快照。

## 9. 自动候选资格硬约束

一个候选必须同时满足：

1. `resource_id` 在当前 ComfyUI 能力响应中存在且为 `ready`。
2. 引擎提供当前匹配契约所需的字段。
3. 资源与参考音频的文件均位于允许根目录，且指纹仍有效。
4. 参考音频明确兼容该 `resource_id`。
5. 命名角色的资源角色和参考音频角色都能通过确认绑定、规范名或受控别名解析到目标角色。
6. 通用角色跨角色时，目标角色必须标记为通用角色，候选必须来自通用声音池。
7. AI 推断字段达到 5.2 节规定的信任下限；资源映射和兼容关系必须是声明或人工确认来源。

受控别名如果同时解析到多个角色，视为歧义并阻断自动匹配。`is_generic` 只有人工确认或静态配置声明时才能放宽跨角色规则，AI 推断不能把角色自动升级为通用角色。

任意硬约束失败都不能通过提高其他分数补偿。

## 10. 可解释评分

合法候选按 100 分计算：

### 10.1 角色匹配：35 分

- 已确认角色绑定：35
- 规范名一致：33
- 受控别名一致：30
- 通用角色进入通用声音池：15

### 10.2 情绪匹配：30 分

- 规范化情绪完全一致：30
- 同一兼容情绪组：22
- 目标情绪缺资源时使用同角色中性参考：12
- 未知或不兼容：0

情绪兼容组使用版本化静态配置，不由运行时大模型临时决定。

### 10.3 时长相似：20 分

```text
relative_error = abs(reference_ms - target_ms) / max(target_ms, 1000)
duration_score = 20 * max(0, 1 - relative_error)
```

### 10.4 语言匹配：10 分

- 参考提示语言完全一致：10
- 引擎明确支持跨语言且语言已知：6
- 未知：0

### 10.5 元数据可靠度：5 分

根据参与评分字段的来源和置信度计算。人工确认或客观测量最高，低置信度推断最低。

### 10.6 阈值与稳定排序

- 总分 `>= 80` 且所有关键字段达到信任下限：可以自动填入。
- 总分 `60..79.999`：只展示推荐，等待确认。
- 总分 `< 60`：保持未匹配。
- 总是最多返回前三名合法候选。
- 同分时依次按人工绑定优先、元数据可靠度、稳定 `candidate_id` 排序。

当台词具有明确的非中性情绪时，自动填入还要求情绪得分至少为 22；同角色中性参考可以进入候选列表，但不能仅凭总分自动填入。

## 11. 目标时长与语速

首版使用轻量、确定性的时长估算：

- 中文按有效字符数计算，初始基准为每秒 4.2 个字符。
- 拉丁语言按单词数计算，初始基准为每秒 2.5 个单词。
- 逗号类增加 150ms，句末符号增加 350ms，省略号和长破折号增加 500ms。
- 中性情绪因子为 1.0；快速、兴奋类因子为 0.9；缓慢、悲伤类因子为 1.15。未配置情绪回退到 1.0。
- 目标时长下限为 600ms。

建议语速由中性估计时长与情绪目标时长的比值产生，并限制在 `0.85..1.20`。超出范围时保留默认语速并要求人工确认，不把 ComfyUI 节点更宽的物理取值范围视为安全范围。

成功生成后只记录字符或单词数量、语言、情绪、最终音频时长和引擎类型，不记录台词文本。相同引擎、语言、情绪至少积累 5 条记录后，使用最近 50 条样本计算出的中位语速率替代静态基准；没有足够样本时继续使用默认值。

## 12. 业务流程

### 12.1 分析后推荐

1. 用户提交剧本并完成语义分析。
2. 已确认或部分确认的台词进入匹配器。
3. 匹配器按当前目录版本返回候选。
4. 高置信度候选填入台词草稿，但不提交任务。
5. 未匹配或低置信度台词保留警告，其余台词继续。

### 12.2 人工检查

右侧台词区域显示：

- 模型类型、`resource_id`、权重组摘要；
- 参考音频、试听按钮、情绪和语言；
- 目标时长、建议语速；
- 总分、置信度、分项得分和命中理由；
- 前三名候选；
- 更换、手动覆盖、保存角色绑定和锁定操作。

### 12.3 资产管理

资产页面显示：

- 扫描根目录和最后同步结果；
- ComfyUI 地址、版本、插件版本和节点能力；
- `ready`、待注册、不可用和仅手动选择资源；
- 缺失或低置信度元数据；
- 权重组与 `resource_id` 映射；
- 重新扫描、编辑元数据和人工确认操作。

### 12.4 提交生成

用户点击生成时：

1. 重新检查选择引用的资源和音频仍存在、就绪且指纹一致。
2. 若目录已变化但引用内容未变化，可基于新目录版本重建等价快照。
3. 若资源、音频或映射变化，阻止该台词并要求重新选择；不静默换候选。
4. 服务端根据 `asset_id` 和 `resource_id` 重建选择；不信任前端提交的分数、路径、兼容关系或资源状态。
5. 将参考音频复制到项目管理的内容寻址任务资产，创建不可变 `VoiceSelectionSnapshot`。
6. 使用现有队列提交 ComfyUI 工作流。
7. 队列工作器在发送工作流前再次校验 ComfyUI 资源状态和配置指纹；变化时失败并保留原选择，不自动换声。

## 13. API 边界

首版增加以下逻辑接口；实际路由遵循当前 `/api` 风格：

- `GET /api/voice-assets/catalog/status`：同步状态、目录版本和能力摘要。
- `POST /api/voice-assets/catalog/sync`：触发一次原子同步。
- `GET /api/voice-assets/catalog`：分页读取资源、参考音频和诊断。
- `PATCH /api/voice-assets/catalog/metadata/{asset_id}`：人工确认或修改元数据。
- `PUT /api/voice-assets/catalog/mappings/{resource_id}`：确认资源与权重组映射。
- `POST /api/projects/{project_id}/voice-recommendations`：为指定台词或全部已确认台词计算候选。
- `PUT /api/projects/{project_id}/lines/{line_id}/voice-selection`：保存、锁定或清除选择。

接口返回稳定错误代码和字段路径。前端不解析英文错误文本决定行为。资产根目录只能引用服务端配置的 `root_id`，同步和元数据接口不接受任意绝对路径；元数据接口不能修改资产路径。所有项目和台词 ID 都通过现有项目边界校验。

## 14. 异常与恢复

### 14.1 台词级警告

- `no_eligible_voice_candidate`
- `voice_match_low_confidence`
- `emotion_metadata_missing`
- `suggested_speed_out_of_range`
- `voice_asset_metadata_unconfirmed`
- `character_alias_ambiguous`
- `manual_voice_identity_override_required`

这些警告不阻止其他台词推荐或生成。

### 14.2 生成阻断

- `comfyui_resource_unregistered`
- `comfyui_resource_not_ready`
- `comfyui_capability_missing`
- `voice_catalog_stale`
- `voice_asset_path_unsafe`
- `voice_asset_changed`
- `comfyui_unavailable`
- `voice_selection_invalid`

网络暂时故障可以按现有队列策略重试。身份、映射、目录版本和路径安全错误不可盲目重试。

### 14.3 一致性

- 扫描失败不覆盖上一份有效目录。
- 推荐引用明确的目录版本。
- 保存人工选择时校验目录版本。
- 提交时再次校验资源状态和资产指纹。
- 队列派发前再次校验 ComfyUI 资源配置指纹。
- ComfyUI 不可用时保留选择和诊断，恢复后可重新提交。

## 15. 插件策略

现有 `TTS-Audio-Suite` 是首选执行插件。开发阶段先检查实际 ComfyUI `/object_info` 和能力接口；只有缺少必要资源类型或输入契约时，才安装额外插件。

额外插件必须：

- 来自明确仓库；
- 锁定提交或版本；
- 记录来源和版本；
- 检查节点名称、输入类型和输出契约；
- 安装依赖后通过独立启动和最小工作流验证。

用户对本次开发所需插件下载已经授权，但产品本身不提供后台静默下载或升级功能。插件安装属于本地部署步骤，不能由普通浏览器 API 触发。

## 16. 安全与隐私

- 后端和 ComfyUI 默认只绑定 `127.0.0.1`。
- 资产根目录通过配置允许列表管理。
- 所有相对路径在读取时解析并重新验证最终路径。
- 试听、任务资产复制和提交生成前都重新解析路径，防止扫描后符号链接或目录联接被替换。
- 不接受前端提交的任意权重绝对路径。
- 不加载来源不明的 checkpoint；checkpoint 加载视为代码执行边界。
- 日志只记录错误代码、阶段、字段路径、资源 ID、目录版本、指纹短标识和耗时。
- 日志不记录剧本文本、API Key、大模型原始响应或完整本地路径。
- AI 元数据补全只接收完成任务所需的最少字段，并沿用现有语义提供者的密钥保护和安全日志规则。
- 文件名、旁路文本和提示词全部视为不可信数据，使用结构化输出和严格字段校验；其中的文字不能触发工具、下载、路径修改或插件安装。
- 系统假设允许根目录由本机受信任管理员维护；大型权重不在每次同步重新计算完整哈希。检测到大小、时间或资源配置变化时必须使旧目录版本失效。

## 17. 代码边界

为了保持核心逻辑轻量，新增代码集中在以下小模块：

- `backend/app/voice_matching_models.py`：目录、候选、快照和 API 模型。
- `backend/app/voice_metadata_inference.py`：复用现有解析器提供者配置的可选结构化元数据补全；推荐阶段不调用。
- `backend/app/voice_catalog.py`：Portable 扫描、ComfyUI 能力合并、原子快照。
- `backend/app/voice_matching.py`：硬约束、评分、时长估算和稳定排序。
- `backend/app/voice_matching_routes.py`：目录、推荐和选择接口。
- `frontend/src/features/voice-matching/`：资产状态、候选卡和选择编辑组件。

`ScriptLine` 增加可选的类型化选择快照，同时继续复用现有 `temporary_binding` 作为可执行绑定。现有 `services.py`、`queue.py` 和 ComfyUI 工作流构建器只接收选择快照投影出的参数；队列已有的 `binding_snapshot` 继续作为生成版本审计记录，不承担目录或排序职责。避免把新逻辑继续堆入 `main.py`、`services.py` 或现有大型工作台组件。

持久化继续使用 `data/` 下的 JSON 文件，不引入数据库。运行生成的数据和本地绝对路径不提交到 Git。

## 18. 测试策略

### 18.1 后端单元测试

- Portable 元数据导入与来源优先级。
- 音频时长测量和路径边界。
- 发现权重与可执行资源的区别。
- 命名角色、受控别名和通用角色硬约束。
- 参考音频与资源角色兼容性。
- 情绪、语言、时长和可靠度评分。
- 阈值、稳定同分排序和前三名裁剪。
- 时长估算、历史中位数校准和安全语速。
- 原子目录更新和上一有效快照回退。
- 选择快照与目录变化校验。
- AI 身份与情绪信任下限，以及推断不能建立资源兼容关系。
- 别名冲突和 AI 推断通用角色不能放宽身份约束。

### 18.2 API 与契约测试

- 模拟 ComfyUI 能力、节点和资源响应。
- 资源未注册、未就绪、插件能力缺失和 ComfyUI 不可用。
- 部分台词成功、部分台词未匹配。
- 人工确认元数据和资源映射。
- 过期目录版本和资产指纹变化。
- 前端伪造分数、路径、兼容关系或 `ready` 状态时由服务端拒绝。
- 同步期间并发读取、重复同步合并和上一快照可用性。
- API 不返回完整本地路径或敏感日志字段。

### 18.3 前端测试

- 自动填入但不自动生成。
- 前三名候选、分项得分和理由显示。
- 参考音频试听、更换、锁定和人工覆盖。
- 命名角色手动跨角色覆盖需要二次确认且不会污染角色别名。
- 未匹配警告持续显示且不会重复堆叠。
- 资产状态、待注册资源和低置信度字段编辑。
- 生成前目录过期提示和重新选择流程。
- 中文和英文文案。

### 18.4 本地集成验证

使用已经人工确认的 GPT-SoVITS 资源完成：

```text
剧本分析 -> 人工确认语义 -> 自动推荐 -> 人工检查 -> 点击生成
-> 验证 ComfyUI workflow -> 获取输出音频
```

验证工作流中的 `resource_id`、参考音频、语言、提示文本、语速和采样参数与选择快照完全一致。CI 不以主观音质判断作为通过条件。

## 19. 验收标准

- 命名角色自动跨角色匹配为 0。
- 只有通用角色可以进入通用声音池。
- 同一输入与目录版本的排序完全一致。
- 高置信度结果只自动填入，不自动生成。
- 低置信度 AI 身份元数据不能驱动命名角色绑定。
- 自动建议语速保持在 `0.85..1.20`。
- 一条台词失败不阻塞其他台词。
- 生成只通过 ComfyUI，不调用 Portable API。
- 未注册权重不能成为生成候选。
- 已确认选择不会被目录变化静默替换。
- 排队期间资源或参考音频变化会失败，不会静默换声。
- 日志不包含剧本文本、API Key、模型原始响应或完整本地路径。
- 人工标注验证集 Top-3 命中率不低于 90%，且身份硬约束零违规。

## 20. 实施顺序

1. 建立领域模型、纯匹配器和失败测试。
2. 建立 Portable 扫描和 ComfyUI 资源目录同步。
3. 增加目录与推荐 API。
4. 将推荐结果接入现有语义台词与生成选择快照。
5. 增加资产状态和台词候选 UI。
6. 完成 ComfyUI 工作流契约验证；仅在现有插件确实缺少能力时安装锁定版本插件。
7. 运行后端、前端和本地 ComfyUI 集成验证。

## 21. 两层自审记录

### 21.1 第一性原理审查

- 将统一元数据优先级改为按语义字段、客观字段和语言分别处理。
- 明确发现权重、资源映射和 ComfyUI 可执行状态是三个不同事实。
- 禁止依据文件名猜测 GPT/SoVITS 可执行配对。
- 将 AI 补全限制在目录同步阶段并按指纹缓存，保持推荐器纯净、确定和轻量。
- 为强情绪增加最低情绪匹配条件，防止中性参考依靠其他分数自动通过。
- 使用大型权重的轻量变化指纹，避免每次同步完整读取模型文件。

### 21.2 对抗性审查

- 服务端重建选择并拒绝前端伪造的分数、路径、兼容关系和资源状态。
- 别名冲突阻断自动匹配；AI 不能把角色升级为通用角色。
- 手动跨角色覆盖必须二次确认，且不会污染角色别名或后续自动匹配。
- 试听、任务资产复制和生成前重新验证最终路径。
- 参考音频入队时固化，ComfyUI 资源在工作器派发前再次验证。
- 外部文件名和旁路文本按不可信数据处理，不能触发工具或安装行为。
